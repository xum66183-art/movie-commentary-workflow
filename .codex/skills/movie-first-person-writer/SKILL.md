# 第一人称电影执笔人

从选定角色的内心讲述电影，不站在上帝视角概括故事。执笔人拥有文稿著作权，同时把镜头数据库和原片当作事实证据。

## 检查前置状态

1. 读取根目录 `AGENTS.md`、`production/state.json`、`project.json`、`INDEX_REPORT.md` 和最新剧情文件。
2. 要求当前状态为有效的 `INDEX_VERIFIED`。索引不完整时，先请求或运行 `movie-index`，不得编造缺失剧情。
3. 新建大纲或整体重写前，读取 [references/writing-method.md](references/writing-method.md)。
4. 提交草稿或锁定修订版前，读取 [references/review-checklist.md](references/review-checklist.md)。

## 理解整部电影

1. 结合字幕、可搜索证据和 8～12 分钟叙事卷，从头到尾理解故事。
2. 对人物决定、关键对白、道具交接、恐怖揭示、身份变化和结局，必须查看带声音的连续原片。
3. 建立按时间排列的事实链和身份链。
4. 理解结局后，反向复查所有因反转而改变含义的早期段落。
5. 明确保留不确定项，不得把视觉模型的猜测升级为剧情真相。

## 选择第一人称叙述者

1. 优先提出拥有最强欲望、盲点、主动选择和命运后果的角色。
2. 与用户讨论第一人称人物，确认后才能锁定。
3. 编写 `POV_BRIEF.md`，记录角色、年龄感、性格、情绪轨迹、语言、声音质感和适合试音的片段。
4. 不得决定最终配音供应商或入选试音；最终声音由用户与 `movie-voice-tts` 共同锁定。

## 撰写草稿

1. 编写 `STORY_MAP.md`，记录时间线、世界规则、身份链、关键道具、信息揭露和结局反查伏笔。
2. 建立第一人称心理主线和信息边界。
3. 设计开场钩子、逐级升级、信念变化、反转、高潮和命运回声。
4. 先写具体动作和感知，再写解释。必要且有画面支撑时，保留高价值原片对白。
5. 只有主角在当时已经知道或能合理推断的信息，才能在对应位置出现。不得为了方便使用全知表达。
6. 有实测语速样本时，按样本估算目标时长；汉字数量只能作为粗略参考。
7. 保存新的不可变版本，例如 `NARRATION_FIRST_PERSON_DRAFT_01.md`。不得覆盖旧稿。

## 自审与编导往返

1. 完成全部文稿检查项。
2. 将草稿标记为 `DRAFT_READY`，交给 `movie-direct` 做文稿预审。
3. 接收包含具体段落、事实和原片区间的审核意见。编导只指出问题，不改写主文稿。
4. 每次修订都新建编号版本，记录修改要求，并保留旧版本哈希。
5. 往返修改，直到编导确认事实、第一人称视角和画面可实现性均通过。
6. 在 `production/state.json` 中记录通过版本的路径和指纹，并锁定为 `SCRIPT_LOCKED`。

## 交付

交付：

- `STORY_MAP.md`；
- `POV_BRIEF.md`；
- 所有编号草稿；
- 最新编导审核；
- 锁定文稿的路径和指纹；
- 一段短试音文案；
- 人名、地名和虚构词的读音说明。

文稿锁定后不得静默修改。任何正文变化都会让整篇配音、时间戳、导演方案和渲染失效。
