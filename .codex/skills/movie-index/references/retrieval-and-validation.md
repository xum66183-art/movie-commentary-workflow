# 镜头检索与验证

## 拆解查询

按需要拆解，不强制每项都存在：

- 角色或可见外貌；
- 地点；
- 有先后顺序的动作；
- 物体或道具；
- 对白片段；
- 大致剧情位置；
- 连续性要求，例如“她进门之前”或“他反应之后”。

联合搜索精确对白、模糊对白、规范化视觉事实和已确认纠错。优先选择有多个独立信号共同支持的候选项。

## 证据包

返回：

- 排序后的候选清单；
- 原片精确 `start_ms` 和 `end_ms`；
- 父技术镜头；
- 重叠字幕；
- 规范化视觉事实和不确定项；
- 代表图；
- 动作前后的至少三张连续画面；
- 带合理前后余量的原声片段。

证据包只帮助定位素材，不能代替观看连续原片。

## 验证清单

接受索引前完成以下检查：

1. 将索引时长与 `ffprobe` 结果对比。
2. 查找时间缺口、重叠、反向区间和重复稳定编号。
3. 核对代表图数量并确认图片可读取。
4. 检查 SQLite 完整性以及必需数据表或结构版本。
5. 确认字幕内容能在预期的时间顺序中被搜索出来。
6. 核对视觉覆盖数量、失败单元数量和续跑能力。
7. 至少测试十条查询，覆盖人物、地点、动作、物体和对白。
8. 对已知回归查询，要求前排结果包含可用答案；如未命中，必须记录，不得隐藏。
9. 打开若干返回片段，确认时间坐标、画面、字幕和声音一致。

## 冲突处理

证据优先级如下：

1. 带声音的连续原片；
2. 原片字幕和精确时间轴；
3. 原片连续画面；
4. 已确认的人工纠错；
5. 视觉模型原始描述；
6. 单张代表图。

证据发生冲突时，保留冲突并回到原片复查。不得把相互矛盾的剧情事实平均成一个看似确定的结论。
