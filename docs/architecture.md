# 架构说明

## 单主脑模型

本项目不是八个岗位互相交接的流水线。`movie-master-director` 是唯一入口，当前 Codex 窗口持续保有剧情、文稿、声音、镜头和用户反馈的完整上下文；其余技能只是按阶段加载的专业能力。

只有用户明确要求并行候选时，才临时使用 `movie-batch-director`。候选只能写入隔离目录，由总导演观看并决定是否采用。

## 四层结构

```text
用户创意门槛
    ↓
总导演与阶段技能
    ↓
状态、锁与数据合同
    ↓
媒体、模型和供应商适配器
```

### 1. 用户创意门槛

用户确认第一人称人物、锁定音色、判断样片方向，并决定是否进入正式全片。技术检查不能代替这些决定。

### 2. 总导演与阶段技能

- 总导演负责连续理解和最终创意责任；
- 索引技能建立证据层；
- 执笔技能控制事实与第一人称边界；
- 配音技能产出音频和时间戳；
- 编导技能决定镜头、节奏和声音意图；
- 渲染技能机械执行锁定方案；
- 二次复检技能从观众视角检查最终成片。

### 3. 状态与数据合同

每个真实影片项目至少包含：

```text
film-project/
├── project.json
├── production/state.json
└── DIRECTOR_MEMORY.md
```

- `project.json`：影片身份、输入来源、媒体参数和稳定配置；
- `production/state.json`：当前采用版本、锁、指纹和下一合法动作；
- `DIRECTOR_MEMORY.md`：跨窗口仍需要的创意理解，不保存可由状态文件推导的数据。

导演方案、混音方案和复检问题分别由仓库中的 JSON Schema 描述。

### 4. 外部适配器

外部能力包括 `ffmpeg`、PySceneDetect、视觉模型、TTS 和 ASR。适配器只返回坐标、证据或媒体产物，不能自动升级为剧情真相或创意决定。

## 证据与责任

证据优先级：

1. 带声音的连续原片；
2. 原片字幕和精确时间轴；
3. 原片连续画面；
4. 经确认的人工纠错；
5. 视觉模型原始描述；
6. 单张代表图。

责任边界：

- 模型负责召回，主脑负责判断；
- 编导负责创意，渲染负责执行；
- 技术验收负责媒体正确性，用户负责创意认可；
- `FINAL_VERIFIED` 必须同时具有正式锁、技术通过和二次复检通过。
